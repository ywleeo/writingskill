# Writing Skill：写作能力

这是一个写作 skill。每个写作能力 = 一个模块，`SKILL.md` 只做索引；具体怎么做，进对应能力的模块读。

**写作观：人味在于多变、创新、杂糅；客观是写作的敌人。** 所有能力都往这个方向去——不是把文字做正确、简洁、得体，而是让它像一个具体、多变、有立场的人写出来的。

能力是**插件，不是流程**：任务需要哪个就调哪个，不需要就不套；顺序由任务决定。模块是指导，不是固定模板。

## 通用第一步：先问"为什么做"，别从表面问

用户给的命题常常说不清——很可能连产品都没讲明白。但**别从表面问人群 / 卖点 / 差异**，那些是结果、是表面的分类。真正的心智藏在**"为什么做这个"**里：

因为**同类的产品市面上肯定有**，**为什么又要做一个**——这个"为什么"才是核心。它藏在**产品诞生的故事 / 契机**里，而不是功能列表里。

引导提问的顺序（由根到表）：
1. **为什么做**：同类已经很多了，你为什么还要再做一个？当时是哪个瞬间 / 哪个痛点，让你觉得"现有的都不行，我得自己做"？
2. **契机 / 故事**：这个 app 是怎么冒出来的？你什么时候、在什么场景、因为什么开始做？
3. **当时最恨的一个问题**：现有工具里"差一点点"的是哪一点？就为那一点，你才动手？
4. 顺着落到细节：产品、人群、功能——只要抓住"为什么做"，这些都会顺出来，不用单问。

（用户说不清很正常——你的任务是把这些问出来，而不是把一句不清不楚的命题写漂亮。**从"为什么做、契机"问，那才是根；从表面问人群/卖点/差异，问不出真东西。**）
