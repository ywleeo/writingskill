# 能力：写一篇能读下去、读完有用的长文

写公众号长文 / 知乎专栏回答 / 头条资讯体那种正文。先立立场和问题链，和用户确认后再写。

## 读者（沿用上游，不重复定）

读者在「总起点」已定。这里只在开写前确认没跑偏；跑偏了就回总起点重新定。

## 先有洞察、立场、中心问题

三个概念，别混：

- **洞察**：要说清的那个非显然的点（发现）。
- **立场**：你对它的态度 + 情绪浓度（赞成/反对、好/坏）。没洞察，立场是空站队；没立场，洞察是冷的结论。
- **中心问题**：读者会被勾住、想知道答案的问题。答案 = 洞察 + 立场。

例（写咖啡）：
- 洞察：咖啡早不止提神，是这届人靠它续命撑过上班的每一天。
- 立场：所以别只写"香"，写那个凌晨还要靠它撑下去的打工人。
- 中心问题：我们为什么越来越靠咖啡活着？

`如有必要，用 titles.md 写几个标题帮确定立场`

## 再设计问题链

对中心问题做问题链，分两种情况。**问题链很难一次写对**：先画草图，心里过一遍读者会不会中途"所以呢"就跑了；不顺手就换，或一次给 2-3 条候选。

注意：读者是普通看客。别堆术语、别做严密论证，给结论 + 说人话，证据点到为止。

- 若话题已有大量代表性讨论（先去知乎/小红书看高赞）：重新设计问题链，一环扣一环；再逐个给出有事实 / 逻辑支撑的看法。
- 若读者还没形成问题：设计一条证明立场的观点链，一环扣一环；预设读者读到每步会问什么，逐个解答。

## 声口锚

立场和问题链定了，去找声口：

1. 去知乎 / 小红书搜同题材高赞内容，学它的**声口**（节奏 / 语气 / 身份）。
2. 只学声口，别参考内容、别抄袭。
3. 篇幅按题材和平台的实际字数，别随口定 800 字。

写时用 [de-ai-flavor](de-ai-flavor.md) 去味。

## 校验

- 立场和问题链，先和用户确认。
- 是不是太严密、像证明，而不是人味足、有意思。
- 声口对不对。
- 用 [de-ai-flavor](de-ai-flavor.md) 过一遍。
