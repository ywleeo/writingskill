# 能力：写一篇能读下去、读完有用的长文

写公众号长文 / 知乎专栏回答 / 头条资讯体那种正文。先确定立场和问题链，和用户确认后再写文章。

每次产出后自己校验一下。

## 先对齐读者

如果参考内容和话题对应的读者，你不明确。或者你觉得选题和你想象的读者关系没那么大，先想用户提问，对齐读者。

必须回答：

- 读者是谁：
- 读者为啥想看这个：

## 先定中心问题和立场

对给定的选题先明确中心问题立场：

用户关心的中心问题只和自己的利益，八卦，猎奇相关，用户不关系真理，不关心和自己毫无关系的事。不要用 AI “解答万物”的 sense 去设计一个和用户毫无关系的呆逼问题。（如用户看到太阳只会想今天热不热，晒不晒，穿啥，涂不涂防晒，而不是太阳的轨迹，气候的原理之类的呆逼问题。用户看到狗打架只会想看哪个狗赢，打的惨不惨，拍照发朋友圈，不会想知道动物的社交冲突模式，做人，不要做 AI）

`如有必要，可以用 titles.md 写几个标题帮助确定立场`

1. 先提炼大众对选题最感兴趣的一个问题（称为中心问题）。
2. 自己先对这个问题有确定的答案（称为定子），比如赞成还是反对，好的还是坏的。
3. 自己的立场也需要能引发读者的好奇心。

## 再设计问题链

对中心问题做问题链的设计，分两种情况。

注意：读者是普通看客，别堆术语、别做严密论证，只给结论 + 说人话。证据点到为止，读者不关心。

### 一、 用户已经对这个话题有诸多代表性的问题（可以搜索知乎/小红书看看高赞的代表性看法），则需要：

```
1. 重新设计问题的链路，让问题连贯流畅，一环扣一环

2. 对每个问题给出回答，即提出有事实或逻辑支撑的看法
```

### 二、 用户对这个话题还没能提出问题，则需要：

```
1. 设计一个证明定子的观点链路，需要一环扣一环，连贯流畅

2. 预设用户看到每个观点会提出的问题，并给这些问题解答，即提出有事实或逻辑支撑的看法
```

## 声口锚

当立场和问题链确定了，寻找合适的声口锚点

1. **去知乎或小红书搜索类似的高赞类容，找到适合表达此内容的声口写内容**
2. **只模仿声口，不要参考内容和抄袭内容**
3. **写作篇幅要按题材和平台的实操字数限制，不要随便定个 800 字。**

**写文章的时候要用** [de-ai-flavor.md ](/Users/leeo/Code/github/ywleeo/ai-writer/writingskill/abilities/de-ai-flavor.md)确保文字有人味

## 校验

- 先校验立场和问题链，并需要和用户确认
- 是不是过于严密和证明感，而不是人味足和有意思。
- 确保内容符合声口锚的写作风格
- 用 [de-ai-flavor.md ](/Users/leeo/Code/github/ywleeo/ai-writer/writingskill/abilities/de-ai-flavor.md)校验内容
